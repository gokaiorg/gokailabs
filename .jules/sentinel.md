## 2026-06-07 - Synchronizing Strict Security Headers (CSP, HSTS, Permissions-Policy) across Environments
**Vulnerability:** The application lacked crucial modern security headers including a strict Content-Security-Policy (CSP), HTTP Strict Transport Security (HSTS), and Permissions-Policy. This exposed the application to various risks like Cross-Site Scripting (XSS), Man-in-the-Middle (MitM) attacks, and unauthorized access to powerful browser features. Additionally, the project uses multiple deployment targets (Netlify via `netlify.toml` and Apache via `.htaccess`), creating a risk of mismatched security configurations.
**Learning:** Modern SPAs require a finely-tuned CSP to allow essential external resources (like Google Analytics, external images, etc.) while blocking everything else. It was critical to identify all domains the application legitimately communicates with (e.g., `region1.google-analytics.com`, `green.gd`) and construct a robust CSP. Furthermore, we must ensure these security headers are perfectly synchronized between `netlify.toml` (for Netlify deployments) and `.htaccess` (for Apache fallback/deployments).
**Prevention:** Always maintain a centralized list of required external domains for the CSP. Whenever updating security headers, explicitly apply the changes to all server configuration files (`netlify.toml`, `.htaccess`, `nginx.conf`, etc.) simultaneously. Use strict, least-privilege configurations for Permissions-Policy and CSP.
