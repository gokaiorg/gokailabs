## 2024-05-18 - Strict Content Security Policy
**Vulnerability:** Missing Content Security Policy (CSP), Strict-Transport-Security, and Permissions-Policy left the application vulnerable to Cross-Site Scripting (XSS), protocol downgrade attacks, and unauthorized access to browser features.
**Learning:** Adding a generic CSP often breaks functionality. In this Svelte application using Vite and external integrations, it's critical to allowlist specific domains for images (`green.gd`, `art-fate.com`, `amann-inkspiration.com`, `ghostverse.org`, `storage.googleapis.com`), scripts (`https://www.googletagmanager.com`), and connections (`https://region1.google-analytics.com`) discovered through codebase analysis, while maintaining `'unsafe-inline'` for styles and scripts due to current constraints of the build setup and Google Tag Manager.
**Prevention:** Always implement a strict, tailored CSP that explicitly defines permitted domains based on actual application usage rather than relying on default or overly permissive settings. Ensure security headers are synchronized across all potential deployment environments (e.g., both `netlify.toml` and `.htaccess`).
