## 2024-05-24 - Missing Content-Security-Policy (CSP)
**Vulnerability:** The application was missing a Content-Security-Policy (CSP) header, which left it susceptible to Cross-Site Scripting (XSS) and data injection attacks by not restricting the sources of executable scripts, stylesheets, and other resources.
**Learning:** CSP is crucial for mitigating XSS risks. The policy must carefully whitelist only necessary domains. In this Svelte application, inline styles and scripts were used in some places (like for GTM and default setups), meaning `'unsafe-inline'` was required, but we strictly bounded the external sources to just the explicitly used domains for tracking (Google Analytics/GTM) and external images.
**Prevention:** Include CSP headers by default in all web application configuration files (like `.htaccess` for Apache and `netlify.toml` for Netlify) to establish a baseline of security, and continually refine the policy to be as restrictive as possible without breaking functionality.
