## 2024-05-14 - Improve dynamic form feedback accessibility
**Learning:** Svelte's conditional rendering (`{#if formStatus.message}`) for form responses visually appears for sighted users, but screen readers may miss the newly injected text entirely. The message div needs `role="status"` and `aria-live="polite"` so screen readers will announce the update. Also, "Sending..." text on a button isn't sufficient without a visual loading indicator (spinner) for better user feedback, and keyboard focus states are crucial for interactive elements.
**Action:** Always wrap dynamically inserted success/error messages in an element with `role="status"` and `aria-live="polite"`. Add visual spinners and strong `focus-visible` styling to form buttons.## 2024-05-18 - Language Switcher Focus State Improvements
**Learning:** Swapping `<span>` and `<button>` elements based on selection state breaks keyboard focus when a user activates a button. For accessibility and usability, maintaining persistent interactive elements (`<button>`) and using `aria-pressed` to indicate state is far superior to structural DOM changes.
**Action:** Always prefer persistent, interactive elements with semantic ARIA state attributes (`aria-pressed`, `aria-expanded`, etc.) over conditional rendering of static vs. interactive tags when representing component state changes.
