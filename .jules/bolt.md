## 2024-05-18 - [Statically Importing Default Locale]
**Learning:** In applications using `svelte-i18n` (or similar i18n libraries), relying solely on dynamic imports (`import()`) for all locale files blocks the initial rendering of the application until the default locale file is fetched over the network and parsed.
**Action:** Always statically import the primary/default locale file (e.g., `import en from './locales/en.json'`) to bundle it with the main JavaScript chunk. This eliminates the network round-trip requirement for the default language and allows synchronous, immediate rendering of the page, drastically improving First Contentful Paint (FCP). Secondary languages should remain dynamic to keep the initial bundle small.## 2024-05-18 - [Svelte Template Allocation Avoidance]
**Learning:** In Svelte templates, using expressions like `Array(n)` within an `{#each}` block will allocate a new array structure on every single re-render of that component, consuming excess memory and garbage collection cycles over time.
**Action:** Extract any dynamic array instantiations used simply for repetition into statically allocated, frozen module-level constants (e.g., `const STARS = Object.freeze([1, 2, 3, 4, 5])`) and use conditional rendering `{#if star <= n}` inside the loop.
## 2024-05-18 - [Regex Compilation Hoisting]
**Learning:** Regular expressions declared directly inside event handler functions (like form submission logic) are recompiled and re-allocated in memory every time the event fires. While JavaScript engines optimize this, it is still a small, redundant overhead.
**Action:** Always hoist regular expression literals (`/pattern/`) out of frequently executed functions to the module scope (or global component scope) so they are compiled exactly once when the module is loaded.
