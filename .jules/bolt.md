## 2024-05-18 - [Statically Importing Default Locale]
**Learning:** In applications using `svelte-i18n` (or similar i18n libraries), relying solely on dynamic imports (`import()`) for all locale files blocks the initial rendering of the application until the default locale file is fetched over the network and parsed.
**Action:** Always statically import the primary/default locale file (e.g., `import en from './locales/en.json'`) to bundle it with the main JavaScript chunk. This eliminates the network round-trip requirement for the default language and allows synchronous, immediate rendering of the page, drastically improving First Contentful Paint (FCP). Secondary languages should remain dynamic to keep the initial bundle small.## 2024-05-18 - [Optimizing Component Render Loops in Svelte]
**Learning:** Instantiating new objects or arrays directly inside the markup (e.g., `{#each Array(n) as _}`) causes unnecessary memory allocation on every render cycle, increasing garbage collection (GC) pressure.
**Action:** Replace dynamic inline instantiations with a frozen static constant defined in the script scope (e.g., `const STARS = Object.freeze([1, 2, 3, 4, 5]);`) and use conditional rendering (`{#if star <= n}`) to achieve the same visual outcome efficiently.
## 2024-05-18 - [Hoisting Regular Expressions]
**Learning:** Defining regular expressions inside frequently called functions (like event handlers or loops) recompiles the Regex and allocates new memory on every invocation.
**Action:** Always hoist static Regular Expressions into the module or component scope to compile them exactly once during initialization.
